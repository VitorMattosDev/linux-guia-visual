Os dois firmwares

BIOS (legado)

  • Executa os primeiros 512 bytes do disco — o MBR.
  • Só 446 bytes úteis: o GRUB precisa se espalhar em estágios.
  • Tabela de partições dos, quatro entradas primárias.

UEFI

  • Lê FAT32: a ESP em /boot/efi, com arquivos .efi por fornecedor.
  • Ordem de boot em variáveis da NVRAM — efibootmgr -v.
  • Teste definitivo: existe /sys/firmware/efi? Então é UEFI.

Na prática
kali@kali: ~
$ ls /sys/firmware/efi && echo UEFI || echo BIOS   # o teste que vale
$ cat /proc/cmdline
BOOT_IMAGE=/boot/vmlinuz-6.12.13-amd64 root=UUID=8f3a... ro quiet splash
$ systemd-analyze
4.512s (firmware) + 2.883s (loader) + 3.201s (kernel) + 11.744s (userspace)
$ sudo efibootmgr -o 0002,0000,0001   # reordena o boot, nao apaga nada
$ sudo update-initramfs -u            # reparo padrao apos trocar disco
Cuidado com efibootmgr -b NNNN -B: apaga a entrada da NVRAM para sempre e pode deixar o outro sistema do dual boot inacessível. Salve antes (efibootmgr -v > ~/efi-antes.txt) e prefira -o, que só reordena. Gravar imagem com dd em /dev/sda destrói o GRUB em BIOS.
⚡ Resumo rápido
  • Diagnosticar "não inicia" é decidir qual dos cinco elos foi o último a rodar.
  • Reinstalar o Windows não apaga o GRUB — só reescreve a BootOrder.
  • O initramfs existe para romper a dependência circular: o driver do disco raiz mora dentro do disco raiz.
  • Tecla e no menu do GRUB edita a entrada só para este boot; Ctrl+X inicia. Nada é gravado.
🐉 No Kali
O live monta um squashfs só-leitura com overlay na RAM — por isso tudo some ao desligar; persistência exige partição rotulada persistence. O modo forense difere só na linha do kernel: não monta nada automaticamente. E Secure Boot não trava o boot, trava o driver Wi-Fi: Required key not available em módulo DKMS é isso — confira com mokutil --sb-state.
