A escada da recuperação — desça um degrau por vez
1
Kernel anterior no menu do GRUB — resolve atualização de kernel que quebrou o sistema. Por isso dois kernels sempre instalados.
2
Tecla e: parâmetro temporário — nomodeset, systemd.unit=rescue.target. Nada é gravado; Ctrl+X inicia.
3
rescue.target — roda o sysinit: raiz montada, fstab aplicado, swap, journal, shell de root. Sem rede.
4
emergency.target — só a raiz, somente leitura, nada montado. É o degrau para quando o problema é o próprio fstab.
5
Live USB + chroot — quando não inicia de forma alguma. Mais poder e mais chance de estragar o sistema errado.

Na prática — o chroot do degrau 5
kali@kali: ~ (live USB)
$ lsblk -f && sudo mount /dev/sda2 /mnt
$ sudo mount /dev/sda1 /mnt/boot/efi   # a ESP: o passo esquecido no 1
$ for d in /dev /dev/pts /proc /sys /run; do sudo mount --bind "$d" "/mnt$d"; done
$ sudo chroot /mnt /bin/bash
# cat /etc/os-release; cat /etc/hostname; ls /home/   # qual sistema e este?
# grub-install --target=x86_64-efi --efi-directory=/boot/efi && update-grub
$ sudo findmnt --verify --verbose && sudo mount -a   # valide ANTES do reboot
Dentro do chroot, confirme em qual sistema você está antes de qualquer comando. Com dois sistemas ou um disco de backup ligado há mais de uma raiz plausível, e um grub-install ou passwd root no lugar errado não dá erro nenhum — o estrago é silencioso e o problema original continua. Na máquina remota, systemctl isolate rescue.target derruba a rede e o SSH junto.
⚡ Resumo rápido
  • nofail em toda montagem não essencial — com x-systemd.device-timeout=10 corta a espera de 90 s.
  • findmnt --verify + mount -a antes de reiniciar: 5 segundos que substituem uma sessão de recuperação.
  • isolate age agora; set-default age no próximo boot.
  • Reparar não é entender: depois que voltar, journalctl -b -1 -p err diz por que caiu — senão cai de novo.
🐉 No Kali
O live USB do Kali é a ferramenta de recuperação que você já tem: traz cryptsetup, lvm2, gdisk, testdisk. Com disco criptografado, abra antes do chroot: cryptsetup luksOpen /dev/sda3 raiz + vgchange -ay. Cuidado com apt autoremove: ele leva o kernel anterior, que é o degrau 1. E modo forense ≠ recuperação — se a máquina puder virar objeto de investigação, imagem com hash primeiro, reparo depois.
