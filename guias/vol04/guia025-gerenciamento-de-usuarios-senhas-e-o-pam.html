As duas camadas para criar uma conta

useradd — baixo nível

  • Padrão de todo Linux. Sozinho escreve só a linha em /etc/passwd.
  • Sem -m não há /home nem cópia do /etc/skel; sem senha, não há login — daí o "não funcionou".
  • Previsível: é a forma certa em script de provisionamento.

adduser — alto nível

  • Script Perl do Debian/Kali que orquestra o useradd com defaults sensatos.
  • Cria e povoa o /home, pede a senha, resolve o grupo primário.
  • É o que você quer na mão. Para remover: deluser --backup --remove-home.
Na prática
kali@kali: ~
$ sudo useradd -m -s /bin/bash -c "Joao Silva" -G sudo joao
$ sudo passwd -S joao      # P valida | L bloqueada | NP sem senha
joao P 08/01/2026 7 90 14 -1
$ sudo chage -l joao | grep -i expira   # o que o passwd -S esconde
Conta expira: dez 31, 2026
$ sudo lastb -n 5          # logins FALHOS: enxurrada = forca bruta
Você quer…ComandoEfeito
Forçar troca no próximo loginchage -d 0 joao · passwd -e joaoExpira a senha; a conta continua utilizável
Senha válida por 90 dias, aviso em 14chage -M 90 -W 14 joaoPolítica de envelhecimento da senha
Desativar o acesso numa datachage -E 2026-12-31 joaoExpira a conta — barrada em account. -E -1 desfaz
Suspender agora / liberarusermod -L joao / -UPõe e tira o ! do hash. Não impede login por chave SSH
Dois comandos que trancam o acesso. usermod -G docker joao sem o -a substitui a lista inteira e tira o joao do sudo (para remover de um grupo, gpasswd -d joao docker). E um erro em /etc/pam.d/ tranca o login de todos, inclusive o root: edite sempre com uma sessão de root aberta em outro terminal e teste numa sessão nova antes de fechá-la.
⚡ Resumo rápido
  • useradd -m em script · adduser na mão; /etc/skel é o molde do /home.
  • Expirar senha ≠ expirar conta — só o chage -l mostra as duas.
  • userdel preserva o /home; -r apaga. Sobram órfãos: find / -xdev -nouser.
  • Quem autentica é o PAM, não o serviço: pam_pwquality (senha forte) e pam_faillock (faillock --reset).
🐉 No Kali
Na VM, sudo adduser analista resolve; deixe o useradd explícito para provisionar. last, sudo lastb e lastlog são a triagem de acesso — e /var/log/wtmp truncado é, por si só, indício de que alguém limpou rastro. PAM é vetor de persistência: módulo adulterado em /lib/*/security/ aceita senha-mestra — confira data e hash contra o pacote limpo. Auditar o próprio sistema ou alvo autorizado é defesa; mexer em PAM alheio é crime (Lei 12.737/2012).
