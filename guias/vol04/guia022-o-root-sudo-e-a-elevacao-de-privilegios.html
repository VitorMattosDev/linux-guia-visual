Root, sudo e
Elevação

Colar sudo na frente resolve o Permission denied — e tira a rede de proteção.
022Guias Linux

Root é o UID 0

O kernel pula quase toda verificação de permissão: lê e escreve qualquer arquivo, mata qualquer processo, abre porta < 1024.

Só 3 limites — removíveis

Precisa de algum bit x para executar · chattr +i trava o arquivo · SELinux/AppArmor impõem política acima. O root desfaz os três.

Menor privilégio

Rode como usuário comum e eleve só o comando. Como root, um rm com um caractere a mais não pergunta nada.

Anatomia de uma regra do /etc/sudoers
quem
%sudo
O % marca grupo. No Kali, kali já é membro.
em quais máquinas
ALL
Vale em qualquer host que receba este arquivo.
como quem
(ALL:ALL)
Pode virar qualquer usuário e qualquer grupo.
quais comandos
ALL
Trocar por uma lista de binários é o coração do menor privilégio.
Os dois caminhos para elevar

su — o interruptor

  • Pede a senha do root e abre um shell persistente: tudo é root até o exit.
  • Todo admin precisa saber a mesma senha, que nunca muda.
  • O log diz só "alguém virou root". No Debian/Kali a senha de root vem bloqueada — su - nem funciona.

sudo — a concessão

  • Pede a sua senha, consulta a política e eleva um comando.
  • Cache de 15 min por terminal — sudo -k invalida na hora.
  • -i = ambiente limpo de root (/root) · -s = poder de root com o seu ambiente.
Na prática
kali@kali: ~
$ sudo -l                    # o que EU posso rodar, sem executar nada
$ sudo -u postgres psql      # sudo nao e so "virar root"
$ sudo visudo -f /etc/sudoers.d/local   # valida antes de salvar
$ sudo journalctl _COMM=sudo --no-pager | tail -1
sudo: kali : TTY=pts/1 ; PWD=/home/kali ; USER=root ; COMMAND=/usr/bin/apt update
Restringir o sudo a……não restringe nada, porque
vim, less, man:!bash / !bash abre um shell de root de dentro do programa
findfind . -exec bash \; executa o que quiser
awk, perl, pythonrodam código arbitrário por definição
cp, tee, dd, tarsobrescrevem /etc/sudoers ou /etc/passwd
Nunca edite /etc/sudoers com editor comum — uma vírgula fora do lugar tranca o acesso administrativo da máquina inteira. Só visudo, que valida a sintaxe antes de salvar. E NOPASSWD: para um comando que escapa (tabela acima) é root completo sem senha.
⚡ Resumo rápido
  • Root é o número 0, não o nome — e ignora os bits rwx.
  • su abre shell persistente; sudo eleva um comando e registra quem foi.
  • Política em /etc/sudoers.d/, sempre via visudo.
  • Regra restrita só vale se nenhum comando dela rodar outro programa.
🐉 No Kali
Root vem bloqueado — mantenha assim; onde um manual antigo pede su -, use sudo -i. nmap -sS, tcpdump e aircrack-ng pedem root porque precisam de socket raw: eleve por comando, não abra a sessão inteira como root. Em teste autorizado, sudo -l é o 1º reconhecimento — a maioria das escaladas nasce de um NOPASSWD mal escrito (ver GTFOBins). Fora de escopo escrito, é crime (Lei 12.737/2012).
