O kernel define

Drivers e suporte a hardware, escalonamento de CPU, memória, sockets. Nenhum programa toca o hardware — todos pedem ao kernel. Monolítico e modular: lsmod mostra o que foi carregado sem reiniciar.

A distribuição define

Biblioteca C, init, shell, gerenciador de pacotes, repositório, instalador e a política de atualização. É onde nasce o apt × dnf — e a janela de suporte.

Os números não conversam

Kernel 6.12.25 e distro 2025.2 não têm relação. Ler os dois é o primeiro diagnóstico de qualquer máquina desconhecida.

As duas perguntas do primeiro minuto
kali@kali: ~
$ uname -a                  # qual KERNEL está rodando
Linux kali 6.12.25-amd64 #1 SMP PREEMPT_DYNAMIC Kali 6.12.25-1kali1 x86_64 GNU/Linux
$ cat /etc/os-release       # qual DISTRIBUIÇÃO foi instalada
PRETTY_NAME="Kali GNU/Linux Rolling"   ID=kali   ID_LIKE=debian
$ dpkg -l | grep -c '^ii'   # o tamanho do trabalho de integração
3184

⚡ Resumo rápido
  • Linux, no sentido estrito, é só o kernel; a distro é o kernel + integração.
  • uname -a = kernel · /etc/os-release = distribuição. Números independentes.
  • Conceitos (processo, permissão, socket) valem em toda parte; comandos, não.
  • Kernel sob GPLv2: quem embarca Linux num roteador devolve o fonte modificado.
🐉 No Kali
Debian rolling da OffSec, saído do ramo testing. O 2025.2 é marco de imagem, não versão congelada — o repositório é kali-rolling e apt full-upgrade é rotina, não evento. Kernel com sufixo -kali1 (patches de injeção e modo monitor), usuário padrão kali desde 2020.1, ferramentas em metapacotes. Não é distro de servidor: é a máquina de quem audita, não a auditada.
