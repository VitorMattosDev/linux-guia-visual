Subshells, agrupamento
e here-documents

O script de implantação tinha uma função com cd "src/$1" e make. O módulo rede compilou; parser e interface falharam com "diretório não encontrado". O cd dentro da função mudou o diretório do script inteiro, e a segunda chamada tentou entrar em src/rede/src/parser. A correção cabe em dois caracteres: ( cd "src/$1" && make ). Saber o que atravessa a fronteira de um subshell — e em que direção — separa quem escreve shell por hábito de quem escreve com intenção.

A fronteira do subshell · e o agrupamento que não tem fronteira nenhuma
shell pai
  • PWD=/projeto
  • contador=0
  • umask 022
  • trap limpar EXIT
  • opções: set -e
herda tudona entrada
só o códigode saída volta
subshell ( … )
  • recebe cópia de tudo
  • cd /tmp → só aqui dentro
  • contador=99 → só aqui dentro
  • exit 1 → encerra só o subshell
  • traps de sinal voltam ao padrão
( comando1; comando2 ) — isola
  • Use para isolar cd, mudar umask ou opção do shell temporariamente, ou rodar algo em paralelo com &. Cada um é um fork: custa.
{ comando1; comando2; } — agrupa
  • Mesmo processo: cd e atribuição persistem e exit derruba o script. Exige espaço depois do { e ; antes do } — são palavras reservadas, não operadores.
Subshells nascem sem que você escreva parênteses: em cada estágio de um pipeline (a | b | c são três), em toda substituição de comando $(…), em todo comando posto em segundo plano com & e em toda substituição de processo <(…) / >(…). É a explicação de n=0; seq 3 | while read x; do ((n++)); done; echo $n imprimir 0: o while rodou num processo que já morreu levando o n junto. O uso legítimo do { } é aplicar um redirecionamento, um | ou um && a vários comandos de uma vez — sem ele seria preciso repetir >> relatorio.txt em cada linha, e a primeira teria de ser > para truncar, exatamente o tipo de assimetria que se erra. E antes de abrir um subshell, verifique se existe uma expansão que faz o mesmo: $(<arquivo) é implementado internamente pelo Bash e não cria processo nenhum (contra dois em $(cat arquivo)); ${f%.log} substitui $(basename "$f" .log); wc -l < "$f" substitui cat "$f" | wc -l. Num laço de dez mil iterações com três substituições cada, são trinta mil processos de diferença.
Here-documents e here-strings: as quatro variantes
expande<<EOF expande $var, $(cmd), \

Quando o bloco precisa de valores do script. Cuidado: um $ literal no texto vira expansão sem aviso.

literal<<'EOF' não expande nada

O padrão para gerar script, configuração e código. As aspas no delimitador são a única diferença visível.

indentável<<-EOF remove as tabulações iniciais

Permite indentar o bloco dentro de um if. Só TAB, nunca espaço — editor que converte TAB quebra em silêncio.

linha única<<< "texto" here-string, sem pipe

read -r a b <<< "$linha" substitui echo | read e evita o subshell: as variáveis sobrevivem.

kali@kali: ~/lab-subshell
# redirecionamento aplicado ao GRUPO: o uso legítimo do { }
$ { echo "=== $(date +%F) ==="; df -h; echo "=== fim ==="; } > rel.txt
# gerar arquivo: aspas no delimitador, SEMPRE, por padrão
$ cat > /usr/local/bin/limpar.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail
for f in /var/tmp/*; do rm -rf -- "$f"; done
EOF
# sem as aspas, $f expandiria AGORA: o disco receberia rm -rf -- ""
# escrever onde exige privilégio — sudo echo > NÃO funciona
$ sudo tee /etc/systemd/system/coleta.service >/dev/null <<'EOF'
[Service]
Type=oneshot
ExecStart=/usr/local/bin/coletar.sh
EOF
# here-string: sem pipe, sem subshell — o read sobrevive
$ IFS=: read -r usuario _ uid _ <<< "kali:x:1000:1000"
$ echo "$usuario $uid"
kali 1000
# isolar o ambiente de UMA invocação
$ ( export HTTP_PROXY=http://127.0.0.1:8080; ferramenta )

Aqui ou lá? o heredoc sobre ssh

  • <<EOFo bloco é expandido localmente: $PARTICAO chega já resolvido, e só o que você escapar com \$ sobra para o remoto
  • <<'EOF'o bloco vai literal: $HOSTNAME é resolvido no remoto
  • teste antestroque ssh servidor por cat e olhe o bloco — um $(…) que você achou que rodaria aqui e roda lá é execução não pretendida na máquina de outra pessoa
  • ssh -nem laço, o ssh engole o resto da entrada e o laço acaba na primeira volta. ssh -n ou < /dev/null

Detalhes que travam o script

  • delimitadorsozinho na linha, sem espaço antes nem depois. Um espaço invisível depois do fechamento é a causa nº 1 de unexpected end of file: o shell lê o resto do arquivo procurando um fim que não chega
  • <<-'EOF'existe e junta as duas coisas — literal e indentável. É a forma de escolha para gerar arquivo de dentro de um bloco aninhado
  • em pipelineo heredoc alimenta o primeiro comando: sort <<'EOF' | uniq -c
  • coprocsubshell com quem se conversa, dois pipes já ligados. Nicho: mais que uma troca de linhas trava em impasse quando o buffer enche
Gerar script com <<EOF sem aspas grava o comando destrutivo já expandido no disco. No bloco for f in /var/tmp/*; do rm -rf -- "$f"; done, se o delimitador não estiver entre aspas o $f é resolvido na hora de gerar o arquivo — e como f não existe no script gerador, o que fica gravado é rm -rf -- "". O defeito só aparece quando o script gerado roda, com o privilégio que ele tiver. Use <<'EOF' por padrão e tire as aspas apenas quando quiser mesmo a expansão. Depois de gerar, leia o arquivo antes de torná-lo executável (cat, shellcheck, e o rm trocado por echo rm num ensaio). Vale o mesmo cuidado em /etc/sudoers.d: valide com visudo -cf arquivo antes de movê-lo para o lugar definitivo — um arquivo malformado ali derruba o sudo da máquina inteira.
⚡ Resumo rápido
  • ( ) cria processo, { } não. Dentro de ( ), cd, atribuição e mudança de opção morrem na saída; só o código de retorno atravessa a fronteira.
  • { } exige espaço depois da chave e ; antes do fechamento — são palavras reservadas, não operadores.
  • Subshells nascem sem parênteses: em cada estágio de pipeline, em toda $(…), em todo & e em <(…). É a explicação do contador que continua zero depois do laço.
  • ( cd dir && comando ) é o idioma para isolar mudança de diretório dentro de uma função — o defeito da abertura, corrigido com dois caracteres.
  • Cada subshell é um fork. $(<arquivo), ${var%sufixo} e wc -l < arquivo fazem o mesmo trabalho sem criar processo.
  • <<'EOF' é o padrão para gerar arquivos; <<EOF é a exceção para quando o bloco precisa das variáveis do script. As aspas decidem se o $ do texto é literal.
  • <<- remove tabulação, nunca espaço. Editor que converte TAB em espaço quebra o bloco de forma silenciosa.
  • <<< substitui echo x | comando e evita o subshell que faria as variáveis do read se perderem.
  • sudo echo x > /etc/arquivo não funciona — quem redireciona é o seu shell, antes do sudo entrar em cena. A forma correta é sudo tee arquivo <<'EOF'.
🐉 No Kali
Gerar arquivo de configuração de ferramenta é caso de <<'EOF', sem exceção. Modelos de proxychains, nuclei e msfconsole são cheios de $, % e \: sem as aspas no delimitador o shell come metade da sintaxe e o arquivo sai sutilmente errado — o tipo de defeito que só se manifesta quando a ferramenta se comporta de um jeito inesperado no meio de um teste. Subshell para isolar o ambiente de uma ferramenta: ( export HTTP_PROXY=http://127.0.0.1:8080; export HTTPS_PROXY=$HTTP_PROXY; ferramenta ) faz o proxy valer só naquela invocação — sem os parênteses, o resto do script continua atravessando o proxy, inclusive comandos que você não pretendia interceptar. No ssh com here-document, a pergunta "aqui ou lá?" tem consequência jurídica: um $(…) que você achou que rodaria localmente e roda no remoto é execução não pretendida numa máquina de outra pessoa — em ambiente autorizado é um erro a corrigir; fora dele, é acesso não autorizado nos termos da Lei 12.737/2012. Teste o bloco com cat no lugar do ssh antes de disparar. sudo tee para instalar unidade ou regra — unidade do systemd, regra de udev, arquivo em /etc/sudoers.d — e sempre visudo -cf antes de mover. E o custo de fork aparece justo na triagem de resultado: um laço sobre dez mil linhas com três substituições por iteração são trinta mil processos; trocar $(cat "$f") por $(<"$f") e $(basename "$f" .log) por ${f%.log} derruba o tempo de minutos para segundos. Família RHEL: subshell e heredoc são idênticos, mas em unidade do systemd com ExecStart= não há shell intermediário em nenhuma das duas famílias — redirecionamento e here-document escritos direto no ExecStart= não funcionam; aponte para um script ou use /bin/bash -c '…' explicitamente. E com SELinux em enforcing, script gerado em /tmp e executado dali costuma ser bloqueado por rótulo: gere em /usr/local/bin e rode restorecon.
