A regra que quase ninguém aprende

Só uma classe se aplica

O Linux checa na ordem: é o dono? senão, está no grupo? senão, outros. Para na primeira que casa.

Em arquivo

r lê o conteúdo · w altera o conteúdo · x executa como programa.

Em diretório

r lista nomes · w cria/remove itens · x atravessa o diretório. Sem x, nada dentro é acessível.

As duas notações do chmod

Simbólica

  • Alvo: u dono · g grupo · o outros · a todos
  • Operador: + adiciona · - remove · = define
  • Ex.: chmod u+x script.sh

Octal

  • Soma dos bits por classe: r=4, w=2, x=1
  • Três dígitos: dono · grupo · outros
  • Ex.: chmod 755 script.sh
Na prática
kali@kali: ~
$ ls -l relatorio.txt
-rw-r--r-- 1 kali kali 2913 ago  1 09:14 relatorio.txt
$ chmod 640 relatorio.txt   # dono lê/escreve, grupo lê, outros nada
$ chmod u+x deploy.sh       # torna executável só para o dono
$ stat -c '%a %A %U:%G' deploy.sh
744 -rwxr--r-- kali:kali
OctalSimbólicoUso típico
644-rw-r--r--Arquivo comum (todos leem, só o dono edita)
600-rw-------Arquivo privado — chave SSH, segredo
755-rwxr-xr-xScript/binário e diretórios navegáveis
700-rwx------Diretório pessoal, script só seu (~/.ssh)
chmod 777 não é solução de nada. Abre leitura, escrita e execução para qualquer usuário da máquina. Se o acesso falha, o culpado quase sempre é a falta de x em um diretório do caminho — não a permissão do arquivo.
⚡ Resumo rápido
  • Três classes (dono/grupo/outros), três bits (rwx = 4/2/1).
  • Só a primeira classe que casa é aplicada.
  • Em diretório, x é o que deixa atravessar.
  • umask define a permissão dos arquivos novos.
🐉 No Kali
O Kali roda muita coisa como root, que ignora os bits de permissão — fácil esquecer que num alvo com usuário normal 644 importa. Guarde chaves e wordlists sensíveis em 700/600.
