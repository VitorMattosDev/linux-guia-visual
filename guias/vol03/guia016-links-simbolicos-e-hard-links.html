Links Simbólicos
e Hard Links

O cat diz No such file or directory — mas o arquivo está ali, dois diretórios adiante.
016Guias Linux
Um aponta para o inode, o outro para um caminho

Hard link

ln dados.txt copia.txt
dados.txtcopia.txt
→
inode 4711links: 2
→
conteúdo
  • Dois nomes legítimos: não existe "o original".
  • Sobrevive a renomear/mover o outro nome.
  • Some só quando o contador zera.
  • Não atravessa sistema de arquivos.
  • Não funciona para diretório.

Link simbólico

ln -s dados.txt atalho
atalho →
inode 9002conteúdo:
"dados.txt"
⇢
inode 4711o alvo
  • Arquivo próprio, tipo l; tamanho = nº de caracteres do caminho.
  • Atravessa sistemas de arquivos e aceita diretório.
  • Pode apontar para o que ainda não existe.
  • Alvo saiu do lugar → link pendurado.
  • Não conta no contador de links do alvo.
As três armadilhas do ln

Ordem dos argumentos

ln -s ALVO LINK — origem primeiro, como no cp. Se LINK for um diretório existente, o link nasce dentro dele com o nome-base do alvo.

-sfn, nunca só -sf

Se o link já aponta para um diretório, ln -sf entra nele e cria o link lá dentro. O -n trata o link como arquivo e substitui de fato.

Relativo × absoluto

O relativo resolve a partir de onde o link está, não de onde você o criou. ln -sr calcula o ../ sozinho — ideal em árvore que será movida.

Na prática
kali@kali: ~
$ ln dados.txt copia.txt # hard link
$ stat -c '%n i=%i links=%h' dados.txt copia.txt
dados.txt i=4711 links=2
copia.txt i=4711 links=2
$ ln -s dados.txt atalho ; ls -l atalho
lrwxrwxrwx 1 kali kali 9 atalho -> dados.txt
$ find . -xtype l -printf '%p -> %l\n'
./config.yaml -> ../antigo/config.yaml
$ namei -l /usr/bin/vi # cada etapa e a permissao
A cadeia do vi no Kali
/usr/bin/vi
↓
/etc/alternatives/vi
↓
/usr/bin/vim.basic
Só o elo do meio muda em update-alternatives --config editor. Nada em /usr/bin é tocado — e a atualização do pacote não desfaz a escolha.
chown -RL pode arruinar o sistema. O -L segue os links e leva a mudança de dono para fora da árvore — um link para /etc dentro de /var/www basta. Use chown -Rh (muda o dono do link, não do alvo) e, antes de qualquer -R em diretório que você não criou, liste o que há lá dentro: find /var/www -type l -ls.
⚡ Resumo rápido
  • Hard link = outro nome para o mesmo inode; simbólico = arquivo com um caminho dentro.
  • -P não segue · -L segue · -H só o da linha de comando.
  • cat e cp seguem o link; rm nunca toca o alvo; cp -a preserva a estrutura.
  • find -xtype l acha os quebrados; namei -l diz qual etapa do caminho barrou.
  • Laço de link devolve ELOOP por volta de 40 níveis — é proteção, não defeito.
🐉 No Kali
/usr/share/wordlists é quase todo feito de links para os diretórios dos pacotes — namei -l mostra onde de fato vão parar, e um apt autoremove agressivo deixa links pendurados (find /usr/share -xtype l). Wordlist gigante em outra partição pede link simbólico: hard link não cruza sistema de arquivos. E monte a pasta de engajamento com ln -sr, para ela sobreviver a ser arquivada e movida.
