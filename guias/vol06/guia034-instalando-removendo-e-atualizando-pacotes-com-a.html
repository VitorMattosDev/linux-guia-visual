apt purge também vai de rc direto a não instalado — é o único caminho que apaga a configuração.
O estado rc é o que faz o apt remove parecer que não funcionou: o binário some, mas o dpkg -l segue listando o pacote. É proposital — reinstalar recupera seus ajustes. Ache os resíduos com dpkg -l | grep '^rc'. Nenhuma dessas transições toca em /home: o gerenciador de pacotes nunca apaga dado de usuário.
upgrade × full-upgrade: o que cada um pode fazer

apt upgrade — proibido remover

  • Pode instalar pacote novo e subir versão. Não pode remover nada.
  • Quando atualizar A exige remover B, ele desiste de A e imprime “foram mantidos”.
  • Serve no Debian stable, onde remoção é exceção e a mensagem é rara.
  • Num rolling é armadilha: cada execução acumula pendência, o sistema fica meio antigo/meio novo — e o full-upgrade adiado vira uma migração gigante de uma vez.

apt full-upgrade — conclui a migração

  • Pode instalar, atualizar e remover o que estiver no caminho. Nada fica pendente.
  • Exige que você leia a lista de remoções antes de confirmar.
  • É o apt-get dist-upgrade de antigamente — mesmo comportamento, nome menos enganoso.
  • Sequência certa: sudo apt update && sudo apt full-upgrade && sudo apt autoremove.
Antes de confirmar

Por que vieram 30 pacotes

Depends é obrigatório; Recommends é instalado por padrão (a origem do volume); Suggests não é. Corte caso a caso com --no-install-recommends — desligar global deixa faltando o firmware e o plugin que tornam a ferramenta útil.

Manual × automático

autoremove age sobre a marcação, não sobre sua intenção: o que entrou como dependência vai embora quando fica órfão. apt-mark manual <pkg> protege o que você passou a usar direto; showmanual e showauto mostram os dois lados.

Simule — e depois conserte

apt install -s imprime o plano inteiro sem sudo e sem tocar em nada. Deu ruim: apt --fix-broken install resolve dependência quebrada e dpkg --configure -a conclui instalação interrompida. apt-mark hold congela — e showhold evita esquecê-lo.

Três cuidados. (1) apt autoremove depois de remover um metapacote propõe apagar dezenas de ferramentas — leia a lista inteira antes do -y. (2) apt purge apaga sua configuração em /etc sem volta; se houver ajuste que interessa, copie antes. (3) No erro Could not get lock /var/lib/dpkg/lock-frontend, nunca apague o lock por reflexo: é quase sempre o unattended-upgrades rodando. Confirme com sudo lsof /var/lib/dpkg/lock-frontend — apagar com um dpkg ativo corrompe o banco de pacotes, e o conserto é pior que a espera.
⚡ Resumo rápido
  • Descobrir: apt search --names-only, apt show, apt rdepends --installed antes de remover biblioteca.
  • apt install ./arquivo.deb (com o ./) instala o local resolvendo dependências — melhor que dpkg -i + conserto.
  • Em script use apt-get: DEBIAN_FRONTEND=noninteractive + -o Dpkg::Options::=--force-confold.
  • O APT não tem undo. /var/log/apt/history.log conta o que houve; desfazer é reinstalar versão a versão — se ainda existir no espelho.
  • No RHEL: dnf já remove para concluir (não há o par upgrade/full) e tem dnf history undo.
🐉 No Kali
apt upgrade sozinho é o comando errado aqui. Num rolling, pacote é renomeado e biblioteca troca de soname: remoção é rotina, e “foram mantidos” é alerta, não ruído. Atualize semanalmente e por inteiro — saltos pequenos e previsíveis; um Kali parado seis meses tenta migrar centenas de pacotes de uma vez, e reinstalar da imagem atual costuma sair mais barato que consertar. Tire snapshot da VM antes de todo full-upgrade grande: é a única rede de segurança real. E rode apt install -s antes de metapacote — o kali-linux-everything passa de 100 GB instalado. Um .deb de terceiro roda script como root na instalação; por isso o /var/log/dpkg.log entra em toda verificação forense.
