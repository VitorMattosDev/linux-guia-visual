Mesmo destino, dois caminhos
/ ├─ etc │ └─ ssh │ └─ sshd_config ├─ home │ └─ kali │ └─ projetos │ └─ recon ← pwd └─ var └─ log
Absoluto — começa em / /etc/ssh/sshd_config Aponta para o mesmo arquivo de qualquer lugar. É o que se usa em script e em cron.
Relativo — parte do pwd ../../../etc/ssh/sshd_config Digita menos, mas só vale a partir de recon. Um cd antes e o mesmo texto aponta para outro lugar — ou para lugar nenhum.
O diretório atual é um campo do processo, não do usuário nem do terminal. Dá para vê-lo por fora em /proc/<PID>/cwd — útil para achar quem segura um sistema de arquivos que você quer desmontar. Daí saem três consequências: cada aba tem o seu; o filho herda e nunca devolve — um script que faz cd move a si mesmo e morre, o seu shell fica onde estava (por isso source); e é por isso que cd precisa ser builtin. Já . e .. são entradas reais do sistema de arquivos, não sintaxe — é o que faz ./script.sh rodar sem o diretório atual estar no PATH.

⚡ Resumo rápido
  • Absoluto começa em / e vale sempre; relativo depende do pwd.
  • Script que faz cd não move o seu shell — para mover, source.
  • Oculto é só nome com ponto: sem -a o seu ~ parece vazio.
  • -F marca o tipo (/ dir, * exec, @ link) e sobrevive ao cano, quando a cor não.
  • Script que lê arquivo ao lado dele: DIR="$(cd -- "$(dirname -- "$0")" && pwd -P)".
🐉 No Kali
O ~ do usuário é /home/kali; o do root é /root — depois de sudo -i o que você salvar não está no seu diretório. É a explicação de "salvei o relatório e não acho mais". O Zsh do Kali liga o AUTO_CD: digitar só /var/log já muda de diretório (não funciona em Bash nem em script), e cd /u/l/b + Tab expande para /usr/local/bin. Ferramenta clonada do GitHub vai para /opt, que não está no PATH — é o caso de uso nº 1 do pushd/popd. Wordlists em /usr/share/wordlists (a rockyou.txt vem .gz numa instalação nova). E faça de ls -la ~/.ssh rotina: chave com permissão frouxa faz o cliente SSH recusar a conexão.
