Personalizando o shell:
.bashrc, aliases e funções

Digitou alias ll='ls -la', gostou, pôs no ~/.bashrc: funcionou em toda aba nova. Escreveu um script com ll, agendou no cron — e às três da manhã chegou um e-mail com ll: command not found. Nada quebrou. O shell só leu outro arquivo.

A seta tracejada é a chave de tudo. O ~/.bashrc não é lido por um shell de login — ele só entra porque a distribuição pôs um source ~/.bashrc dentro do ~/.bash_profile. Apague a linha e o SSH perde os aliases; o script não lê nenhum dos dois. Os testes: shopt -q login_shell e [[ $- == *i* ]] — a letra i em $- só existe em shell interativo, daí todo .bashrc de distribuição abrir com case $- in *i*) ;; *) return;; esac: sem a guarda, um banner ali entra no meio da saída e quebra scp e rsync.

alias — troca a 1ª palavra
  • Substituição textual, só da primeira palavra, antes de executar.
  • Argumento sempre no fim: alias x='cmd --opt' não põe nada no meio.
  • sudo ll falha — contorne com alias sudo='sudo ' (com espaço).
  • Não vale em script: expansão vem desligada.
  • Escape pontual: \grep ou command ls — o alias de cor suja o pipeline.
função — comando de verdade
  • Tem parâmetros, lógica e código de saída. Faz tudo que o alias faz.
  • mkcd(){ mkdir -p -- "$1" && cd -- "$1"; } — impossível como alias.
  • Robustez: --, aspas em toda expansão, local, erro em stderr.
  • export -f alcança subshells Bash, e só eles.
  • O que precisa valer em script vem de biblioteca com source, não do .bashrc.
Na prática — os ajustes de maior retorno diário
kali@kali: ~ — em qual shell eu estou?
$ ps -p $$ -o comm= ; echo $SHELL
zsh                       /usr/bin/zsh
# editar ~/.bashrc aqui nao muda NADA
$ type ll        # alias? funcao? binario?
ll is an alias for ls -alF --color=auto
$ bash -n ~/.bashrc && echo "sintaxe ok"
# checa SEM executar. Um erro ali te deixa
# sem shell utilizavel no proximo login.
$ shellcheck ~/.bashrc ; bash -lic 'exit'

Nunca ponha . (o diretório atual) no PATH, muito menos no início. Com ele lá, entrar num diretório escrito por outra pessoa e digitar ls executa o ls plantado ali: escalada de privilégio clássica, trivial de explorar, inteiramente evitável — use ./programa, a barra torna a intenção inequívoca. E pense antes de alias rm='rm -i': ele treina o reflexo de confirmar sem ler, e no servidor, no contêiner ou dentro de um script — todos sem o alias — o rm apaga sem perguntar. Prefira alias rmi='rm -i' ou uma função-lixeira, deixando o rm real com o comportamento real.
⚡ Resumo rápido
  • Login, interativo e nenhum dos dois lêem arquivos diferentes. O script e o cron não lêem nem .bash_profile nem .bashrc — é a causa do command not found das três da manhã.
  • Ambiente no .bash_profile, comportamento interativo no .bashrc. O .bashrc roda a cada aba: tem de ser rápido e silencioso — banner ali quebra scp e rsync.
  • O Bash lê só o primeiro entre .bash_profile, .bash_login e .profile. Criar um .bash_profile onde só havia .profile apaga o PATH em silêncio.
  • Alias troca a primeira palavra e morre no script; quando precisa de argumento no meio, de lógica ou de código de saída, é função.
  • histappend + HISTCONTROL=ignoreboth corrigem os dois piores padrões do histórico: sobrescrita pela última aba e duplicata.
  • bash -n antes de confiar. Um erro de sintaxe no arquivo de inicialização é a via mais rápida para ficar sem shell utilizável.
🐉 No Kali
O shell padrão é o Zsh desde o Kali 2020.4 — e é aqui que quase todo mundo tropeça: o usuário kali tem /usr/bin/zsh no /etc/passwd, com um ~/.zshrc de mais de cem linhas mantido pelo pacote kali-defaults. O ~/.bashrc continua lá, íntegro, para os contextos que usam Bash — então o alias que você acrescentou ao ~/.bashrc simplesmente não aparece no terminal, e nenhum erro indica isso. Confira com ps -p $$ e echo $SHELL antes de escolher o arquivo. O Zsh tem cinco arquivos onde o Bash tem dois, e o ~/.zshenv é o único dos dois shells lido sempre, inclusive por script: o lugar certo do PATH e o pior possível para qualquer coisa que imprima. O kali-tweaks troca o prompt sem editar arquivo, mas escreve em arquivos do pacote — atualizar o kali-defaults sobrescreve edições manuais em /usr/share/kali-*; personalização sua vai no ~/.zshrc. Trocar de shell é chsh -s /usr/bin/bash, nunca editar o /etc/passwd na mão — e vale só no próximo login, o que faz muita gente achar que falhou. Root tem /root/.zshrc próprio: seus aliases não valem sob sudo -i, e assim deve ser. Fora do Debian: Bash é Bash, mas o Fedora/RHEL chama /etc/bash.bashrc de /etc/bashrc e usa /etc/profile.d/*.sh intensamente — dotfile portável testa a existência antes do source.
