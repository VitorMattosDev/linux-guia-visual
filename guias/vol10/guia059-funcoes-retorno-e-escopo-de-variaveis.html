retorno e escopo

O inventário contava pacotes com return "$n". Na instalação enxuta imprimia 180 — certo. Na estação com o kali-linux-everything, 4.412 pacotes, imprimiu 60. Sem erro, sem aviso: o valor não coube no canal. Uma função tem dois caminhos para devolver informação, e o script escolheu o estreito.

Os dois canais de saída — dado ≠ veredito
função contar_pacotes

Um comando novo, indistinguível de ls para quem chama — e com precedência sobre o programa externo.

Saída padrão

n=$(contar_pacotes)

Texto de qualquer tamanho. Cabe 4412, cabe uma tabela inteira, cabe um caminho com espaços. Custo: o $( ) cria subshell — variável atribuída lá dentro morre junto — e remove as quebras de linha do fim.

Código de saída

contar_pacotes; $?

Inteiro de 0 a 255, e só. O return responde deu certo?, não qual é o resultado?. return sem argumento devolve o código do último comando — o que se quer numa função-predicado como usuario_existe() { id "$1" >/dev/null 2>&1; }.

return 00
return 11
return 255255
return 2560 falha vira sucesso
return 30044
return 441260 o bug da abertura
Como devolver dados de verdade
n=$(contar_pacotes)

Idiomática. A função imprime, o chamador captura. Comporta-se como função de verdade — ao custo de um processo por chamada, o que pesa em laço apertado.

RESULTADO=… ; contar_pacotes

Global por convenção. Sem subshell, a mais rápida. Cria acoplamento invisível: quem lê a chamada não vê que a variável mudou. Nome em MAIÚSCULAS e comentário na linha acima.

local -n destino="$1"

Referência nomeada (Bash 4.3+): o chamador escolhe onde o resultado vai parar. Prefixe o nome interno (__destino) — passar variável homônima dispara erro de referência circular.

local x=$(cmd) engole o erro do comando (SC2155): local é um comando, e o $? que sobra é o dele — quase sempre zero. Declare numa linha, atribua na seguinte: local v; v=$(cmd) || return 1. Vale igual para declare, export e readonly.
Escopo dinâmico: vale a pilha, não o texto
nível superior

segredo não existe aqui — nem antes nem depois da chamada.

↓ chama
externa() { local segredo="abc"; … }

Dona da variável. Ao retornar, o valor anterior é restaurado.

↓ chama
interna() { echo "$segredo"; }

Vê abc sem receber nada como argumento.

Em C ou Python o escopo é léxico — definido por onde a função está escrita. No shell é definido por quem chamou quem em execução. Sem local, toda variável da função é global; e um local i sobrescreve o i de qualquer função chamada abaixo. Em biblioteca, nada de i, n, tmp ou arquivo.
Encerrar, envolver, e quando promover a função a script
as três armadilhas do dia a dia
# exit encerra o SCRIPT; return encerra so a FUNCAO. Biblioteca nunca chama exit.
morrer() { printf 'erro: %s\n' "$*" >&2; exit 1; }   # unica excecao legitima

# 'command' pula a funcao e chama o programa real -- sem ele, recursao infinita
rm() { command rm -i "$@"; }     # legitimo no ~/.bashrc, armadilha dentro de script

# $0 continua sendo o SCRIPT dentro da funcao; o nome da funcao esta em FUNCNAME
$ quem() { echo "$0 | ${FUNCNAME[0]} | chamado por ${FUNCNAME[1]:-<script>}"; }

⚡ Resumo rápido
  • Uma função é um comando, não uma função matemática: recebe posicionais ($1, "$@"), tem precedência sobre o programa externo e precisa ser definida antes da chamada. Prefira a forma POSIX nome() { … } — function não sobrevive a um #!/bin/sh.
  • return devolve código de 0 a 255, nunca um valor. return 4412 vira 60 e return 256 transforma falha em sucesso. Dado sai pela saída padrão.
  • Sem local, toda variável da função é global — inclusive os contadores de laço, a fonte nº 1 de colisão silenciosa.
  • Escopo dinâmico: o local é visível em tudo que a função chamar abaixo, nunca acima.
  • local x=$(cmd) descarta o código de saída de cmd. Declare numa linha, atribua na seguinte.
  • $0 é o script, não a função — use ${FUNCNAME[0]}, e a pilha inteira em FUNCNAME, para o log dizer de onde o erro veio.
  • command evita a recursão infinita ao envolver um comando; builtin força o builtin. Em script, dê nome próprio à função em vez de mascarar o comando.
🐉 No Kali
Função de varredura não chama exit. Num script que percorre alvos autorizados, abortar o programa inteiro porque um host não respondeu descarta o trabalho já feito nos anteriores — o relatório parcial de dezoito alvos vale mais que nenhum relatório. Devolva return com código por tipo de falha (1 host inalcançável, 2 fora do escopo, 3 ferramenta ausente) e deixe o laço decidir se continua. E cuidado com o efeito colateral: se essa função for chamada dentro de $( ), o exit mata só o subshell e o script segue como se nada tivesse acontecido. A validação de escopo pertence a uma função, e ela devolve código, não texto: no_escopo "$alvo" || continue é legível e testável isoladamente; a validação escrita inline em quatro pontos do script garante que uma das cópias vai divergir — e varrer fora do escopo contratado é crime pela Lei 12.737/2012. Não sobrescreva nmap, curl ou ping com função de mesmo nome: quem lê nmap -T4 conclui que a taxa é a do -T4, sem ver o --max-rate escondido vinte linhas acima. Chame de nmap_lento — o nome documenta a intenção. local em função que manipula credencial não apaga nada da memória: ele controla visibilidade, não conteúdo. E não use export -f em script que eleva privilégio — função exportada é código que viaja no ambiente, e foi exatamente essa forma de transporte que o Shellshock (CVE-2014-6271) explorou.
