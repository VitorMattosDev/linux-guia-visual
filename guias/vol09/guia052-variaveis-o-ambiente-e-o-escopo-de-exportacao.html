Quais arquivos cada shell lê — e por que o cron não lê nenhum

Shell de login

console, ssh, su -
  • /etc/profile
  • /etc/profile.d/*.sh
  • ~/.bash_profile
  • ~/.profile (que chama o .bashrc)

Interativo, sem login

nova aba do terminal
  • /etc/bash.bashrc
  • ~/.bashrc
  • e mais nada — o resto vem herdado

Não interativo

script, cron, systemd
  • nenhum arquivo lido
  • PATH mínimo (/usr/bin:/bin)
  • sem TERM, sem aliases
A coluna vermelha é a resposta ao mistério: o .bashrc nunca foi lido, logo o PATH que você acrescentou lá não existe. Correções, em ordem: 1. caminho absoluto para cada comando · 2. export PATH=... explícito no topo do script · 3. PATH= no próprio crontab. Chamar o .bashrc de dentro do script é a saída tentadora e errada — ele tem código de sessão interativa e pode abortar cedo. Para a máquina inteira: /etc/environment (pares simples, lido pelo PAM) ou um fragmento em /etc/profile.d/.

Segredo em variável de ambiente é segredo exposto. O ambiente de um processo vive em /proc/PID/environ, legível pelo dono e pelo root — e é herdado por todo filho, inclusive o instalador de pacote que resolveu mandar telemetria. Por argumento (--senha s3nh4) é pior ainda: aparece no ps aux para qualquer usuário da máquina. Em ordem: 1. arquivo 600 lido com source · 2. entrada padrão (--password-stdin) · 3. gerenciador (pass, secret-tool) · 4. prefixo de um comando só, nunca export na sessão. E nunca segredo dentro de script versionado: apagar a linha num commit posterior não apaga nada do histórico.
⚡ Resumo rápido
  • Sem espaço em volta do =. Com espaço, nome vira nome de comando — daí o command not found que engana quem vem de outra linguagem.
  • export é a fronteira entre variável do shell e de ambiente. A herança é por cópia e de mão única: o filho altera só o retrato que recebeu.
  • Shell não interativo não lê arquivo nenhum. PATH explícito no topo ou caminho absoluto — a correção do cron.
  • SHELL é o shell de login do /etc/passwd, não o em execução (ps -p $$ -o comm=). E LANG muda a saída dos comandos: script que interpreta saída fixa LC_ALL=C.
  • Vazio ≠ não definido. ${VAR:-x} cobre os dois; ${VAR:?msg} aborta cedo com mensagem sua.
🐉 No Kali
O sudo limpa o ambiente — e isso quebra script. O env_reset está ligado no /etc/sudoers: um export CHAVE=v seguido de sudo meu.sh chega ao script sem a chave. Saídas: sudo CHAVE=v comando, sudo -E (preserva tudo — cuidado) ou env_keep via visudo. O Kali põe /usr/sbin e /sbin no PATH de qualquer usuário, porque quase toda ferramenta de rede vive ali — por isso tcpdump e iptables completam com Tab sem sudo, e depois falham com Operation not permitted; compare printenv PATH antes e depois de sudo -i. Conheça as variáveis das ferramentas: PROXYCHAINS_CONF_FILE, HTTP_PROXY/NO_PROXY, GOPATH — proxy configurado no ~/.profile e esquecido é a origem clássica de "a rede parou depois do reboot". Em laboratório, HISTCONTROL=ignorespace mantém credencial de teste fora do ~/.bash_history (no Zsh, setopt HIST_IGNORE_SPACE). E em live USB sem persistência tudo que você exportou some no desligamento: use PATH explícito e caminho absoluto, a mesma disciplina do cron.
